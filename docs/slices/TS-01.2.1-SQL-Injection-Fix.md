## Descrizione
Rifattorizzare la funzione get_devices_by_type in energy/services/device_service.py per utilizzare l'ORM di Django invece di query SQL raw.

## Obiettivo Tecnico
Sostituire query SQL raw con ORM Django per eliminare completamente la possibilità di SQL injection.

def get_devices_by_type(device_type):
    # VULNERABILITÀ: Concatenazione stringhe in query
    query = f"SELECT * FROM energy_device WHERE type = '{device_type}'"
    cursor = connection.cursor()
    cursor.execute(query)
    results = cursor.fetchall()

    for row in results:

        devices.append(device)
    
    return devices

def get_measurements_by_device(device_id, start_date, end_date):

#### Dopo (Sicuro)
```python
def get_devices_by_type(device_type):
    # SICURO: Utilizzo ORM Django
    devices = Device.objects.filter(device_type=device_type)
    return list(devices)

def get_measurements_by_device(device_id, start_date, end_date):
    # SICURO: Utilizzo ORM Django
    measurements = Measurement.objects.filter(
        device_id=device_id,
        timestamp__gte=start_date,
        timestamp__lte=end_date
    )
    return list(measurements)
```

## Test di Accettazione

### Test 1: Protezione SQL Injection
```python
def test_sql_injection_prevention():
    # Test con input malevolo
    malicious_input = "'; DROP TABLE energy_device; --"
    devices = get_devices_by_type(malicious_input)
    
    # Verificare che la tabella esista ancora
    assert Device.objects.count() > 0
    # Verificare che non ci siano dispositivi
    assert len(devices) == 0
```

### Test 2: Query ORM Corretta

def test_orm_query_correctness():
